# 交付验收

每篇分别记录 pass / fail / not_run / blocked。脚本只检查机械不变量，不能自动证明事实正确、结构完整或审稿完成。

## 内容及文件

- 原稿 SHA-256 与提取时一致；源 Word 仍在作者目录。
- 原稿每段、标题、图注、表格与成稿逐一对应；每处实质修改在独立审查记录中有原句、替换句和理由。没有无意遗漏、重排、复制另一篇文字。
- 正文无审稿意见、修改依据、协作说明、调试/工具引用、占位符、重复标题；Word 无修订痕迹/批注残留。
- 三种格式的文件名同一日期、原标题、作者，零填充且无连接符 `+`；文件名的修改后不泄入读者标题。
- 固定四段结尾完整出现一次；表格行列、单位、数值与成稿一致。Markdown 列表不出现空项、错位加粗或整文代码围栏。

## 图片

对照原 DOCX 中实际使用的媒体清单、提取资源、修改后 DOCX 媒体和 HTML 解码字节，逐个比较 SHA-256。不能只检查 HTML 上写着的 data-sha256 属性。

同时检查数量、出现顺序、重复次数、位置、长宽比、图注和署名；仅看唯一哈希集合不够。文档中未引用的旧媒体、备用格式、页眉logo应单独解释，不盲目塞入正文。图中技术/拼写错误作为独立风险告知用户，遵守原图不改的边界。

## HTML

在 390×844 手机与 1440×900 桌面视口检查每篇完整文章，至少保存首屏、全页和表格局部截图。有很长标题、竖图、宽表格时加 320px 窄屏检查。

执行 `scripts/qa_html.mjs` 可检查：页面/元素横向溢出、图片加载/比例、布局标识和隐藏正文，并保存截图。随后必须人工查看截图：标题断行、字色/底色对比、列表正文可见、段落间距、章节顺序、图片位置、表格阅读性、结尾完整和无大段空白。脚本通过不代替截图审阅。

在获得操作授权并可用时，再做公众号后台实际粘贴预览：核对全文文字、强调、列表、表格、图片、图注和尾部。只预览不发布；测试可能更改草稿，应先确认目标草稿/测试范围。没做后台测试就明确记 `not_run`。

## Word

渲染为 PDF/逐页 PNG 并审阅全部页面。可用打包的文档技能 renderer，或本机 WPS/Word 导出 PDF，再用 PDF 渲染工具；缺少渲染器时说明实际使用方法和限制，不把结构通过写成视觉通过。WPS 自动化只关闭自己打开的文档/进程，避免影响用户会话。

检查孤行、标题只剩单字另起一行、标题悬空、图注与图片/表格分离、表格跨页表头/截断、结尾字号过小/挤压、页眉页脚重叠。必要时局部调整分页/间距，不删内容凑页数。重生成后检查的是最新版本。

## 备份与最终说明

本地验收后备份到指定共享目录，读取副本验证 SHA-256，记录目标路径和文件哈希。网络不可用保留本地成稿，明确备份未完成；不删除本地文件、不假称成功、不用其它外部网盘替代。

不同内容同名副本需要确认版本归属后才能显式替换；相同哈希可幂等跳过。更新后重新验证最新备份，不能引用旧备份检查结果。

最终简述处理篇数、格式/目录、备份状态，以及仍需用户处理的风险。内部审查记录可以单独提供链接，不能加回读者正文。只对实际验证的项目声明通过。
