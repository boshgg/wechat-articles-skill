# 项目约定

这些是截至 2026-09-07 的用户要求，后续明确要求可以覆盖。配置见 `assets/project-defaults.json`，运行时核实目录是否存在；迁移机器时显式传入参数。

## 文件组织

| 用途 | 本项目路径/规则 |
| --- | --- |
| 项目 | `E:\公众号文章` |
| 原稿 | `未修改Word/<作者姓名或作者：姓名>/`，只读；新稿已分类时不搬动 |
| 已修改 Word | `修改后Word/`，平铺，不按作者分类 |
| Markdown | `Markdown/`，直接保存，不进入“未发布” |
| HTML | `html文章/`，直接保存 |
| 图片 | `Markdown/assets/<文章唯一标识>/`；已有 `html文章/assets` 相对引用可以继续使用 |
| 内部记录 | `审查记录/` |
| QA 中间文件 | `_work/qa/<批次或文章唯一标识>/`，不作为最终文章交付 |
| 知识库 | `E:\金蓬知识库`；可用全文索引为项目 `知识库索引/knowledge.sqlite` |
| HTML 备份 | `\\Lunnenghuanbao\共享文件\6、运营推广\7、微信公众号` |

不要把 `html文章/已发表` 当作缺失输出而重新生成或移回。扫描时排除临时锁文件 `~$*`、输出目录、测试稿与中间文件。用来源路径和源哈希判定增量，不只看修改时间。多个副本或日期/作者有冲突时先核对，不臆造身份。

## 文件命名

采用 `YYYY.MM.DD原标题（修改后）作者姓名.ext`，适用于修改后的 `.md`、`.docx`、`.html`。审查后存在内容修订的文章加“（修改后）”；当前生产工具延续项目处理稿统一带该标识的惯例。

- 年四位，月日补零，以便文件名排序对应日期排序。
- 不使用字段连接符 `+`；若原标题含有有意义的“C++”等符号，先判断，不能机械删除正文标题中的合法内容。
- 去掉标题中重复的日期、作者、文件版本尾缀，只删确认是元信息的部分，不删题意中的年份或姓名。
- 日期优先用原稿明确文章日期或文件名日期；无日期时用可解释的稿件批次/文件时间，并在内部记录依据。不能把报道中的项目事件日期冒充稿件日期。
- 作者优先取作者目录，并核对文内署名/文件名；“作者：”不是姓名的一部分。
- 不允许非法文件字符或同名覆盖。内容不同但同名时保留原文件，先解决来源/版本冲突。
- “修改后”只在文件名，不放进读者看到的标题或正文。原始 Word 不为迁就成稿命名而覆盖；用户明确要求整理原稿名时，保持作者目录、原始字节与旧新路径映射。

## 原文、素材、结尾

原标题、章节顺序、段落主要内容、作者语气和原有图文对应关系均保留。拆分过长段落可在原有语义边界进行，但不得重写正确内容、补造导语或强行套成“五个坑”。

封面和插图只使用用户提供的材料。保留原始图片字节、比例、顺序、图注、署名及原有 AI 图披露；不得裁剪、压缩、调色、加字、重编码或生成替代图。图片有错误时，在独立审查记录和交付说明提醒用户换图，原图不擅改，文章内不加编辑意见。

文章末尾按 `assets/company-closing.md` 原文追加四段公司介绍一次。现有原文已有完全相同结尾时去重；不同版本不能叠加。该固定文案是用户指定口径，不等于已对全部资质做实时核验。发现明确过时或风险时在内部说明，未经明确授权不自行改写固定介绍。

## 历史规则冲突

最新生效口径为：放宽逐项举证、最小修改、读者视角、原图不动、Markdown 平铺、新版深蓝金色模板、HTML 双份备份。旧文档里的绿色编号模板、强制给每个统计补证据、正文标题加修改后、正文插入审查依据、Markdown/未发布等要求均不再沿用。

## 权限与迁移

技能复用不授予微信公众号发布、外部素材上传、自动索引所有磁盘、删除历史文件或 GitHub 上传业务资料的权限。网络备份仅发送指定 HTML 到用户指定共享目录。分享 skill 时只分享规则、代码、模板和无业务数据的测试，不分享原稿、知识库、客户图片、索引数据库、凭据或批次清单。
